## 先講為什麼要做這件事

任何 AI 系統要能回答你的問題，前提是它**取用得到正確、結構化的資料**。

如果資料散在 Google Drive、LINE 群組、個人電腦和某個人的腦袋裡，再厲害的工具也無能為力。這是我們在[導入 AI 的第一步]({{root}}blog/ai-first-step/)那篇提過的：知識庫是地基。

而且就算你短期內不打算導入 AI，光是「東西找得到」這件事本身就值得。

## 為什麼是 Notion

不是因為它最好，是因為它**門檻最低**。

它的資料庫功能足以支撐結構化管理，但不需要工程背景就能操作。對多數中小團隊來說，能不能被非技術同事實際使用，比功能強不強重要得多。

如果你已經在用其他工具（Confluence、飛書、Obsidian），下面的架構邏輯一樣適用，只是介面不同。

## 四個核心資料庫

重點是**用資料庫（Database），不是用一堆散落的頁面**。資料庫可以篩選、排序、關聯，頁面不行。

### 一、客戶／專案

| 欄位 | 類型 | 用途 |
| --- | --- | --- |
| 名稱 | 標題 | |
| 狀態 | 選項 | 洽談中／進行中／已結案／暫停 |
| 產業 | 選項 | 之後可以篩「所有醫療客戶」 |
| 負責人 | 人員 | |
| 開始日期 | 日期 | |
| 服務項目 | 多選 | |
| 關聯文件 | 關聯 | 連到「文件」資料庫 |

每一筆的內頁放這個客戶的所有脈絡：需求、決策紀錄、注意事項。

### 二、文件

報價單、合約、提案、報告全部放這裡，不要放在雲端硬碟的資料夾階層裡。

| 欄位 | 類型 |
| --- | --- |
| 文件名稱 | 標題 |
| 類型 | 選項（報價／合約／提案／報告／範本） |
| 客戶 | 關聯到客戶資料庫 |
| 日期 | 日期 |
| 版本 | 文字 |

**關聯欄位是關鍵。** 設好之後，打開任何一個客戶就能看到他的所有文件，不用去翻資料夾。

### 三、SOP／作業流程

這個資料庫的價值在於它同時是**新人訓練教材**和**自動化的規格書**。

| 欄位 | 類型 |
| --- | --- |
| 流程名稱 | 標題 |
| 分類 | 選項（投放／素材／報表／行政） |
| 頻率 | 選項（每日／每週／每月／不定期） |
| 負責角色 | 選項 |
| 最後更新 | 日期 |
| 可自動化 | 核取方塊 |

**「可自動化」那個欄位特別有用。** 當你之後要導入自動化時，直接篩選這個欄位就知道從哪裡開始。

### 四、決策紀錄

這是最常被忽略、但長期價值最高的一個。

記錄「我們為什麼這樣做」。例如：

- 為什麼某個客戶的預算配置是這樣
- 為什麼放棄某個投放策略
- 某次危機處理的經過與結論

| 欄位 | 類型 |
| --- | --- |
| 決策事項 | 標題 |
| 日期 | 日期 |
| 相關客戶 | 關聯 |
| 結論 | 文字 |
| 後續驗證 | 文字 |

半年後有人問「這個當初為什麼這樣決定」，你有答案。

## 命名規則：進得去也要找得到

架構再好，命名亂了一樣找不到。訂三條規則就夠：

**一、日期一律開頭，格式 `YYYY-MM-DD`**

```
2026-08-15 騰域 提案簡報 v2
```

這樣排序自然就是時間序。

**二、客戶名稱用統一版本**

不要一下「騰域」一下「騰域整合行銷」一下「TENGYU」。訂一個，全部用它。

**三、版本用 `v1` `v2`，不要用「最終版」「真的最終版」**

這條看起來像玩笑，但它是真實存在的問題。

## 與 AI 的串接

架構建好、資料填進去之後，就可以接 AI 讓人用問句查詢：

- 「上次幫醫療客戶做的提案架構是什麼」
- 「我們對房地產客戶的標準報價流程」
- 「去年這個時候的檔期操作結論」

**能不能問得到，完全取決於前面的結構化做得好不好。** 這也是為什麼我們一定先做知識庫再談自動化。

## 維護規則：決定這是專案還是資產

這是最容易被跳過、但決定成敗的一步。

沒有維護機制的知識庫，三個月後就會變回一團亂，然後大家慢慢不用了。

至少要有這三條：

**一、指定一個負責人。** 不是「大家一起維護」，那等於沒人維護。

**二、訂一個固定的整理時間。** 例如每月最後一個週五，花一小時檢查有沒有沒歸檔的東西。

**三、新東西一律先進資料庫再開始做。** 不要「先做完再補紀錄」，那個補永遠不會發生。

## 一個務實的起步建議

不要一次建四個資料庫。

**先建「文件」一個就好。** 把最近三個月的報價、合約、提案搬進去，用兩週看看團隊有沒有真的在用。

有用，再加第二個。沒用，先找出為什麼不用——通常是命名規則太複雜，或是搬東西進去的步驟太麻煩。

一次建完四個資料庫、訂好完整規則、然後沒人用，是我們看過最常見的失敗方式。

## 重點整理

1. 用**資料庫**不要用散落的頁面
2. 四個核心：**客戶／文件／SOP／決策紀錄**
3. **關聯欄位**是價值所在，讓資料互相串起來
4. 命名規則訂三條就夠：日期開頭、客戶名統一、版本用 v1 v2
5. SOP 資料庫加一個「**可自動化**」欄位，之後直接篩
6. **維護機制**決定它是資產還是廢墟
7. **先建一個資料庫就好**，有用再擴充
